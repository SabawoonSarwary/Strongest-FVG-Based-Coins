# Security Policy

## Supported Versions

Security updates will primarily be provided for the latest version of the project available on the `main` branch.

| Version | Supported |
| ------- | --------- |
| Latest (`main`) | :white_check_mark: |
| Older versions | :x: |

Older versions may not receive security updates. Users are encouraged to keep their local copies up to date.

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please report it responsibly.

**How to report:**

1. Visit the repository's GitHub Security tab.
2. Use the **Report a vulnerability** option if private vulnerability reporting is enabled.
3. Provide a clear description of the issue and steps to reproduce it.
4. Include relevant logs or screenshots if available.

Please do not disclose security vulnerabilities through public GitHub issues before they have been reviewed.

If private vulnerability reporting is unavailable, contact the repository maintainer through their GitHub profile.

## What to Include

When reporting a vulnerability, please include:

- A description of the vulnerability.
- Steps to reproduce the issue.
- The potential impact.
- Affected files or components.
- Any suggested fixes, if available.

Please avoid including API keys, passwords, personal information, or other sensitive data in reports.

## Scope

This policy covers security issues related to:

- The Python FVG detection and analysis toolkit.
- Binance public market-data integration.
- Data processing and CSV exports.
- Dependencies and external interactions.

This project is an educational research tool. It does not execute trades, manage user funds, or require Binance API credentials.

## Response

Reports will be reviewed by the repository maintainer.

Depending on the severity and complexity of the issue, additional investigation or a fix may be required.

Please allow reasonable time for review before publicly disclosing a vulnerability.

Thank you for helping keep this project secure.
